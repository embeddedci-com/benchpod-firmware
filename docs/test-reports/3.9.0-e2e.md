## usb-bridge

With Ethernet stopped (console `eth stop`), Wi-Fi cleared and `benchpod usb-bridge install`
(launchd agent): the pod's cloud link came up through the bridge (cloud `connected` with Ethernet
`disconnected`). Over that link, SDK cloud passed 6 tests and hwe2e `TestCloud` passed 47 with 15
skipped. The one failure was the external LAN policy test pointed at the USB link, which the
policy does not cover; it now skips there. `lsof` showed nothing holding the USB console during
the whole run. `usb-bridge uninstall` cleared the pod's proxy; `eth start` restored Ethernet.

The web app's "uplink: usb" needs server #117 deployed. It is checked against production after the deploy.

## Findings fixed during the run

1. **CLI 0.5.1 install-blobs hung on 3.9.0.** It waits for `upload-begin ok|error ...`; the moved
   line (`upload-begin: moved ...`) matched neither, so it timed out with no hint. The upload
   commands now answer `upload-begin error moved to the network API ...` and `upload-sig` answers
   `unknown command 'upload-sig': moved ...`. Re-tested: 0.5.1 stops at once with the update hint
   (fw 7497df4).
2. **Refusal texts named only the USB console.** CA/proxy changes from Ethernet/Wi-Fi now say
   `change it from the cloud or over USB`, and a locked LAN says `needs the cloud or USB`. CLI, SDK and
   hwe2e accept both the old and the new text (fw b1137ab, 52433a2).
3. **hwe2e's bench reset cleared the usb-bridge proxy**, taking a pod with Ethernet stopped
   offline mid-suite. It now keeps a proxy on the USB link, and the proxy tests skip while one
   is set (server 6180551).
4. **hwe2e LAN policy check used a TCP connect.** 3.9.0 keeps the listener for the USB link and
   resets external connections under `off`, so "LAN up" now means a JSON ping is answered
   (server 32fbbbb).
5. **SDK LA host-clock test race over USB.** Events ran past the 4 s acquisition and went out back
   to back after the read-back; over the faster USB link one hit the previous step train. Now 18
   events inside the capture (python db35d17); 3/3 over USB, 2/2 over Ethernet.
6. usb-bridge help text still described the older console step (cli 2ecdc87).
7. **Linux: `usb` needed the console, which a user outside `dialout` cannot open.** `/dev/ttyACM0`
   is `root:dialout 0660`, so the CLI said "no bench-pod console found" and never reached the USB
   network adapter. The CLI (network commands, policy show, install-blobs, CA/proxy) and the SDK
   now take the pod's address from this computer's end of the USB link (a `/30` in
   `10.237.0.0/16`, `getifaddrs`) before the console; `usb:<name>` picks by `identity_public`. A
   console refused for permissions now says so with the `dialout` / udev fix, and the udev rule
   adds `TAG+="uaccess"` for the desktop user (cli 6e2ce55, 1f89d34; python 189ae5e; server
   ca3b8dc docs).
